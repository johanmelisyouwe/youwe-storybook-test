# CMS integration (Contentful)

This Storybook is the source of truth for the Youwe site. Every template is built from blocks, and every block takes its content as props. This page lists the data shapes so a Contentful entry can be mapped onto a block one to one.

## Conventions

| What | Prop type | From Contentful |
|---|---|---|
| **Image** (every `image`, `poster`, `images[]`, `featureImage`, `backgroundImage`) | `string \| { src, alt?, width?, height? }` | `{ src: 'https:' + asset.fields.file.url, alt: asset.fields.description }` |
| **Logo** (Case Card, Stat, Hero logo bar, Technology logos, Testimonial, Quote Card, Technology Card) | `ReactNode \| { src, alt }` (a code logo or an asset) | An SVG/PNG asset: `{ src, alt: the client }` |
| **Rich text** (Text column, Text + media, Case intro, Two-column text, Section header, Accordion items, Content tabs, Stats outcomes) | `string \| string[] \| ReactNode` | `documentToReactComponents(field)` from `@contentful/rich-text-react-renderer`. Use plain elements (`p`, `h3`, `h4`, `ul`, `ol`, `li`, `a`, `strong`, `em`, `blockquote`, `img`, `hr`). The block styles them. |
| **Links** | `{ label, href }` | A link entry, or `{ label: entry.title, href: '/' + locale + '/' + entry.slug }` |
| **Video** | `string` (file URL or Vimeo URL) | An asset URL or a Vimeo URL field |
| **UI text** (buttons, aria labels) | `labels?: Partial<…_LABELS>` | Translations per locale; every component exports its English defaults, e.g. `CASE_CAROUSEL_LABELS`. Placeholders such as `{count}` are filled by the component. |
| **Regions / locales** | Header and Footer `regions: { label, href, hreflang, current }[]` | One entry per Contentful locale (Global `/`, UK `/en-gb`, NL `/nl`, SE `/sv`). The Header's `homeHref` points the logo to the locale home. |
| **Device** | `'Desktop' \| 'Mobile'` | Not from the CMS: `useDevice()` (below 768px is Mobile), or pass `Device="Auto"` to Header and Footer |

Components with `labels`: Header, Footer, Ask Youwe (bar, snippet, dock), Case carousel, Filter bar, Insights overview, Build your stack, Contact CTA, Testimonial, Breadcrumbs, Insight Card, Pagination, Video Player, Phone input, Cookie banner, Upcoming events. Other button texts are already props (`cta`, `button`, `submit`, `Hover CTA`, `closeLabel`).

## Ask Youwe (answer service)

`AskDock` (on every page) sends questions to the site; the site answers through its own server-side API route, so no key reaches the browser.

```tsx
<AskDock
    locale={locale} // e.g. 'nl'
    context={page.askQuestion}
    labels={askLabels} // panelTitle, loading, error, retry, sources, unavailable, close, send, followUp…
    Prompt={askLabels.prompt}
    fallback={askLabels.unavailable} // shown while there is no service
    onAsk={async (question, locale, { signal }) => {
        const res = await fetch('/api/ask', {
            method: 'POST',
            body: JSON.stringify({ question, locale }),
            signal,
        })
        if (res.status === 503) throw new AskUnavailableError() // → fallback text
        if (!res.ok) throw new Error(String(res.status)) // → error + Try again
        return res.json() // { text, sources?: [{ title, url }], followUps?: string[], cta?: { label, href } }
    }}
/>
```

- **States:** loading (dots and `labels.loading`), answered (text with blank lines as paragraphs, or rich text; source links; follow-up chips; CTA), error (`labels.error` plus Try again), unavailable (`fallback`, or `labels.unavailable`).
- **No `onAsk`:** every question shows the fallback text.
- **Newest question wins:** a new question aborts the previous request through `signal`.
- **Focus:** opening moves focus into the panel's follow-up field. Closing (Esc or the close button) returns focus to where it was: the bar, or the snippet or card that asked.
- **Voice input:** a mic button in the bar and the follow-up field, where the browser supports speech recognition (Chrome, Edge, Safari; hidden in Firefox).
  - While listening, a live wave follows the microphone level and the words appear in the field. The question is asked through the same `onAsk` when the speaker stops.
  - The language follows `locale`.
  - The browser asks for microphone permission. If it is refused, the field says so.
  - Labels: `voice`, `voiceStop`, `listening`, `voiceDenied`, `voiceError`.
- **Questions from elsewhere on the page:** Ask snippets ("Ask about it"), AI Feature Cards and `askYouwe(question)` all open the dock and go through the same `onAsk`.

## 404 and error pages

The site runs on Next.js (app router). The `app` folder in this repo has working examples:

| File | Shows | Notes |
|---|---|---|
| `app/not-found.tsx` | `NotFoundPage` (Templates/404) | Unknown URLs and `notFound()` |
| `app/error.tsx` | `ErrorPage` (Templates/Error) | Error boundary: when a page throws, this replaces it and the layout stays. `reset` → "Try again"; `error.digest` → the error reference (find it in the server logs). Report the error to the error tracker here. |
| `app/global-error.tsx` | A bare fallback with the same copy (`ERROR`) | Only when the root layout itself fails: own `<html>`/`<body>`, no header or footer |

Nested routes can add their own `error.tsx` to keep the failure local (for example only the Insights overview).

## Contentful mapping tips

- **One content type per block.** Model a page as a list of section entries (a reference field allowing the block types above), with a `Device`-free entry per block. A small switch maps each entry's content type to its block.
- **Variants are Figma names.** Props such as `Layout`, `Mode`, `Variant` and `Type` take the exact Figma variant names (for example `'Two-up'` or `'Full width 3'`). Use Contentful "dropdown" validations with the same values.
- **Mode per section.** Wrap a block in `Section Mode="Dark" | "Light"` (or set `data-theme` on its wrapper). Store `mode` on the section entry.
- **Optional sections render nothing when empty.** Leave the section out of the list instead of passing empty arrays.
